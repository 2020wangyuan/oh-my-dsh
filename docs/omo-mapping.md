# OmO → oh-my-dsh Module Mapping

**Overview.** oh-my-dsh is a *port of oh-my-openagent's (OmO) core ideas* onto the DeepSeek Harness (DSH) Dynamic Cordis Plugin system — same concepts (hash-anchored editing, rules injection, comment hygiene, category delegation, team fan-out, "do not stop until done" discipline), re-implemented as in-process plugins against DSH services (`fs`, `systemPrompt`, `subagents`, `goals`, `commands`, `sandboxPolicy`), not a code copy of the upstream TypeScript packages.

Upstream verified at `/home/dministrator/Re/oh-my-openagent` (branch state with `rules-engine`, `delegate-core`, `team-core`, `hashline-core`, `agents-md-core`, `comment-checker-core`, `omo-opencode`); DSH side verified at `src/omo-core/{host,client}.js` and `src/omo-discipline/host.js`.

## 1. Core Mapping Table

| 1 | **hashline-core** — line content-hash anchored read/edit. | 2 | **agents-md-core** — per-file upward AGENTS.md discovery (`processFilePathForAgentsInjection` + `findAgentsMdUp`), session-scoped injection cache, truncation with `[Note: Content was truncated…]` notice | **`systemPrompt.section` `omo-rules`** (order 150) + `/init-deep` command | Injects `AGENTS.md` from the **workspace root only** (not walked up from the edited file), cached and refreshed every 60 s. Dropped: proximity-based upward walk, per-session dedupe cache, truncation, README.md injection (upstream "Context Injection" covers AGENTS.md/**README.md**/conditional rules). `/init-deep` keeps the hierarchical AGENTS.md generation idea (walks ≤2 levels, skips node_modules/.git/…, writes skeletons). |

Kept: background mode (`await:false` → returns child id), text-only result truncation. |

Dropped: upstream's run-level continuation machinery; ours nudges within the same session loop. |

## 2. Architecture Differences

| Dimension | Upstream OmO (Ultimate / OpenCode) | oh-my-dsh (DSH Dynamic Cordis Plugin) |
| :--- | :--- | :--- |
| Host model | Standalone **agent orchestration** loaded into OpenCode; Sisyphus + 10 more named agents as OpenCode AgentConfigs with per-agent model routing | **In-process delegation**: the session agent itself delegates to subagents through the `subagents` service; no separate agent registry, no per-agent models |
| Parallel infra | **git worktrees** per member (`team-worktree`), **mailbox** with consumed-ledger/leases (`team-mailbox`), **tasklist** with claim/dependencies (`team-tasklist`), persistent **state store** with resume/locks | **No per-member workspace or message bus**: all members share one workspace; communication is one-way prompt → final report; no claim/dependency model, no resume |
| Team size | 1 lead + up to **8** members (`max_members: 1..8`, `max_parallel_members` default 4) | 1 lead (calling agent) + up to **6** members (`members.slice(0, 6)`) |
| Live visualization | Real-time **tmux layout** (focus + grid panes, rebalance, caller-tmux resolution) showing every member working | **Text aggregation** — `Promise.allSettled` awaits all members, then renders one "team report" card in the chat (Client surface); work is visible only through per-child state |
| Result passing | Members exchange structured `message`/`announcement` messages with references mid-run | Results collected only at the end; no mid-run coordination |
| Rules injection | `rules-engine`: multi-source rule dirs, frontmatter `when:` conditions, distance ordering, per-session caches, AGENTS.md walked up from the current file | Flat root `AGENTS.md` + `.omo/rules/**`, 60 s cache refresh, injected via `systemPrompt.section` at every prompt assembly |
| Hashline | xxHash32 (native/JS), 2-char dictionary codes, chunked streaming, normalization/autocorrect/diff layers, legacy-hash compatibility | FNV-1a 32-bit → 6-hex codes, full-file read/write, 5 ops (`replace/delete/insertAfter/insertBefore/append`), batch abort on any mismatch |
| Lifecycle surface | 54+ lifecycle hooks (61 with Team Mode), hooks/commands/skills/MCPs from Claude Code ecosystem | A handful of plugin events: `tools/result`, `goal/changed`, `agent/turn-stopping`; commands `/omo`, `/init-deep`, `/ulw` |
| Failure handling | `retry-guidance` / `retry-patterns` (delegate-core), model fallback chains, session recovery | Single-execution delegates with `timeoutMs` caps and error strings folded into the tool result; subagent start failures become per-member failure entries in the team report |
| Comment checking | Spawns a compiled `comment-checker` binary + `apply_patch` static analysis | Inline regex scanner, 4 slop patterns |
| Telemetry | Anonymous PostHog telemetry on by default (`telemetry-core`, opt-out flags) | **None** — not ported (privacy-preserving choice) |

## 3. Not Ported / Deliberately Downgraded

| OmO capability | Status in oh-my-dsh | DSH-side substitute / rationale |
| :--- | :--- | :--- |
| tmux live terminal & Team Mode tmux layout (`team-layout-tmux`, `tmux-core`) | Not ported | DSH runs in the browser; terminal/REPL UX is the harness's own session/tool surfaces; team activity is a text report card, not panes |
| 11 named discipline agents with per-agent model tuning (oracle, librarian, explore, atlas, momus, metis, multimodal-looker, sisyphus-junior) | Reduced to 4 category personas | Subagents are generic; categories only swap the persona preamble (Hephaestus=deep, quick, visual, Prometheus=ultrabrain) |
| Team worktree / mailbox / tasklist / state-store infra | Not ported (by design) | Members share one workspace; coordination is fan-out + end-aggregation; the harness's subagent service is the whole backend |
| Real-time Team Mode visualization + `team_*` tool family (`team_create`, `team_send_message`, `team_task_create`, `team_status`) | Collapsed into a single `omo_team` tool | One-shot team lifecycle: define members → spawn all → `Promise.allSettled` → report |
| Model selection & fallback chains for delegate categories (`resolveModelForDelegateTask`) | Dropped | `omo_delegate` uses the first available subagent provider; category = prompt persona only |
| Built-in MCPs (Exa websearch, Context7 docs, grep_app) | Not ported | DSH has its own `web_search` tool; no context7/grep.app equivalents |
| LSP suite (`lsp-core`, `lsp-daemon`, `lsp-tools-mcp`), AST-Grep (`ast-grep-mcp`) | Not ported | DSH has native language tooling surface; OmO modules kept out of scope |
| `comment-checker` binary + `apply_patch` analysis | Downgraded to regex | `omo_comments` is dependency-free; covers the 4 most common "AI slop" classes only |
| Hashline polish layers (normalization, autocorrect-replacement, canonicalization, diff) | Not ported | The 5-op batch validator with `expectHash` already prevents stale writes; robustness layers left for follow-up |
| IntentGate (true-intent analysis) | Downgraded to keyword trigger | ULW activates on `ulw`/`ultrawork` prefix or goal-worthy requests; no separate intent classifier |
| Session recovery / model fallback / doctor command | Partial | `/omo` shows module status; no recovery machinery (DSH session layer covers some of it) |
| Telemetry (`telemetry-core`) | Not ported | Deliberate omission for privacy |

## 4. Verified Upstream Facts Behind This Mapping

- **hashline-core top-level exports** (read from `src/index.ts`): xxHash32-based `computeLineHash`/`computeLegacyLineHash`, `formatHashLine(s)`, `streamHashLinesFromUtf8/Lines`, `parseLineRef`/`validateLineRef(s)`/`normalizeLineRef`, `applyHashlineEdits(WithReport)`, primitives `applySetLine/ReplaceLines/InsertAfter/InsertBefore/Append/Prepend`, `getEditLineNumber`, `collectLineRefs`, `detectOverlappingRanges`, `dedupeEdits`, text-normalization, file-canonicalization, autocorrect-replacement-lines, `normalizeHashlineEdits`, `createHashlineChunkFormatter`, diff utils.
- **rules-engine** (read `src/index.ts`, `constants.ts`): `PROJECT_RULE_SUBDIRS = [".omo/rules", ".claude/rules", ".opencode/rules", ".sisyphus/rules"]`, `OPENCODE_USER_RULE_DIRS`, `USER_RULE_DIR`, frontmatter parser, `shouldApplyRule` matcher, `calculateDistance`, `findProjectRoot`, caches. `.sisyphus/rules` is deprecated (migration warning to `.omo/rules`).
- **team-core top-level exports** (read `src/index.ts`, `types.ts`, `config.ts`): `team-layout-tmux`, `team-mailbox`, `team-tasklist`, `team-state-store`, `team-worktree`, `team-registry` (incl. `caller-team-lead`), `member-parser`, `session-client`, `logger`, `config`, `types`. `TeamSpecSchema` requires `leadAgentId` (or `lead:`/`isLead:true`) for multi-member teams, max **8** members, `backendType: "in-process" | "tmux"`; `TeamModeConfigSchema` defaults `max_parallel_members: 4`, `max_members: 8`.
- **11 agents** (read `omo-opencode/src/agents/builtin-agents.ts`, `types.ts`, `plugin-handlers/agent-config-assembly.ts`): the `BuiltinAgentName` union lists 10 (sisyphus, hephaestus, oracle, librarian, explore, multimodal-looker, metis, momus, atlas, sisyphus-junior); **prometheus** is assembled at config build time (`buildPrometheusAgentConfig`) into `agentConfig.prometheus`, giving the 11 the README advertises.
- **delegate-core** (read `src/index.ts`, `model-selection.ts`): exports `resolveModelForDelegateTask` with `DelegateFallbackEntry` fallback chains + provider hint/model variant, plus `retry-guidance` and `retry-patterns`. README category table: `visual-engineering` / `deep` / `quick` / `ultrabrain`.
- **comment-checker-core** (read `src/index.ts`, `runner.ts`): `resolveCommentCheckerBinary`/`runCommentChecker` spawn the `@code-yeongyu/comment-checker` binary; separate `apply-patch-edits.ts` static-analysis helpers.
- **om-discipline DSH side** (read `omo-discipline/host.js`): ULW prompt section (order 152), `/ulw` → `goals.create(agent, {maxGoalRounds: 50})`, checkpoint audit to `.omo/ulw-loop/<session>.md` (30 s throttle, 12 max), nudge via `agent/turn-stopping` + `agent.steer`, category personas, `omo_team` with 6-member cap and `Promise.allSettled`.

## 5. Potential Follow-up Work (based on facts, not speculation)

1. **rules-engine matcher + frontmatter conditions** — upstream `when:`/`glob:` metadata and `calculateDistance` give conditional, proximity-based rule application; DSH loads rules unconditionally and flat. Porting `shouldApplyRule` semantics would make `.omo/rules/**` actually conditional.
2. **AGENTS.md upward walk** (`findAgentsMdUp`) — upstream injects the nearest AGENTS.md chain for the file being touched; DSH injects only the root file. Proximity injection would match context to the active file.
3. **Hashline robustness layers** — `normalizeHashlineEdits` (raw model edit → hashline ops), `edit-text-normalization`, `autocorrect-replacement-lines`, and `generateHashlineDiff` are cheap, self-contained wins; also a pure-JS xxHash32 for closer parity with upstream (still hash-format-incompatible, so a deliberate compat decision either way).
4. **delegate model routing** — a DSH-side category→provider/model map (with fallback to first available) would restore upstream's "category, not model" without needing model-core's full resolver.
5. **Team mid-run messaging (lightweight)** — upstream's mailbox enables member-to-member handoff; a DSH version could let `omo_team` members read a shared `.omo/team/<session>/` notes file or accept a `parent`-scoped stub message. This is the biggest missing piece of real Team Mode, but only worth it if fan-out tasks genuinely need cooperation.
6. **`retry-guidance` / `retry-patterns`** — upstream encodes when and how delegation failures should be retried; DSH currently surfaces errors as strings.
7. **Session-scoped rule injection cache with truncation** — upstream dedupes injected AGENTS.md per session and truncates long files with a notice; DSH re-injects everything every 60 s (token cost on large rule sets).
